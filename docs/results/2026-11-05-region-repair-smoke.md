# RegionRepair 冒烟测试（rr_smoke2）：结果与限制

*日期：2026-11-05。数据：CHTC 上的 `rr_smoke2`（`MODE=repair`，源 run 为 `comp_v2`，1 个 seed）。
任务只有 `adult_sit_river_01` 的 3 个目标（`to_beach`、`to_city`、`to_forest`）。代码：提交 `3aba231`
（`src/refinement/region_repair.py`、`experiments/region_repair.py`）。结果包：`results/result_rr_smoke2_dog_sit_river_01.tar.gz`，
其中的 `runs/rr_smoke2/repair.csv` 是下面所有数字的来源。*

## 结论

**3 个任务、1 张源图的冒烟结果，不能说明局部修复有效，也不能说明无效。** 它只说明流水线跑通了，
并且给出了一个需要在规模化时重点检验的信号：错位对照（E）与真实区域修复（B）没有拉开差距。

## 做了什么

对 `comp_v2` 的最终结果，分别用两种接触区形状（`rect`：脚下的矩形；`footprint`：沿轮廓投影的足迹区）做五种处理，
用冻结的 critics 重新打分（探索性 critics 关闭）：

| 变体 | 含义 |
|---|---|
| A_none | 不处理（基线） |
| B_contact | 只修接触带 C |
| C_boundary | 只修边界带 B |
| D_both | C + B 都修 |
| E_misplaced | 面积和形状与 C 相同、但放在远离主体处的区域（对照：排除"只是多做了一次 inpaint"） |

## 结果

下表为相对 A_none 的变化量，三个任务的平均（括号内为各任务的值）。

**overall**

| 变体 | rect | footprint |
|---|---|---|
| B_contact | +0.004（−0.010, +0.003, +0.018） | −0.001（0.000, −0.015, +0.011） |
| C_boundary | +0.004（+0.010, −0.015, +0.016） | +0.004（同 rect，区域相同） |
| D_both | −0.018（−0.012, −0.037, −0.004） | −0.027（−0.058, −0.038, +0.013） |
| E_misplaced | +0.006（+0.011, −0.013, +0.018） | −0.004（0.000, −0.030, +0.018） |
| **B − E** | **−0.002**（−0.021, +0.015, 0.000） | **+0.003**（0.000, +0.015, −0.007） |

**world**（overall 的变化几乎全来自这里）

## 能说和不能说的

可以说：
1. 流水线能跑通：5 个变体 × 2 种形状 × 3 个任务 = 30 行，gate 全部通过，keep 基本不变。
2. **B−E 的均值接近 0**（overall −0.002 / +0.003，world +0.002 / +0.008），且各任务的符号不一致。
   在这个样本量下，没有迹象表明"修对位置"优于"修错位置"。
3. D_both（同时修 C 和 B）在两种形状下的平均都是负的（world 最多 −0.065），区域越大越容易伤到 world 分。

不能说：
1. **三个任务来自同一张源图，实际上只有 1 个聚类**。同一张图的三个目标高度相关，按源图做 cluster bootstrap 无法进行。
2. `footprint` 的 B_contact 在 `to_beach` 上与基线完全相同（overall 0.881，world 0.705），而修复区域有 6945 像素。
   这可能是 inpaint 没有改变足够多的像素，也可能是被后处理还原。**没有检查图像，不能判断是哪一种**。
3. 没有目视检查生成图（`results/rr_smoke2_montage.jpg` 存在，但本文没有基于它下结论）。
4. 只有 `comp_v2` 一个源 run、1 个 seed；没有和全图重编辑（F）、best-of-N 重采样（G）比较。

## 对后续工作的含义

- 止损条件不变：规模化后，B/C/D 相对 E 的配对差值，按源图做 cluster bootstrap 的 95% CI 下界必须大于 0，
  否则 RegionRepair 作为负结果写进论文，不再投入。
- 规模化至少需要 dev 划分（`_01`、`_02`，10 张源图、60 个任务）；在 15 张源图的设定下，聚类数最多是 15，
  CI 会很宽，所以要把"没有显著性"当成可能的最终结果。
- 先目视检查 `footprint` 的 B_contact 为什么没有改变分数，再决定是否需要调整 inpaint 的 mask 膨胀或 prompt。
