# E2 人工标注：计划与执行方法

*日期：2026-10-03。前置：[full-budget v2 结果与计划](../results/2026-10-03-full-budget-v2-runs-and-plan.md)。
工具：`experiments/e2_build.py`（抽样、匿名化）、`experiments/e2_label.py`（本地标注网页）、`experiments/e2_analyze.py`（统计）。*

---

## 0. 为什么要做、要回答什么

critic 判 comp 胜 qwen 75/90，但看图 qwen 更自然。在人工标注之前，我们**不能**说 critic 有偏差，也**不能**说它是对的。
E2 要回答四个问题，每个都有事先定好的判定标准（先定标准再看结果，防止事后解释）：

| | 问题 | 指标 | 判定 |
|---|---|---|---|
| H1 | 人更喜欢 qwen 还是 comp？ | 成对「整体偏好」的 qwen 胜率（不计平局），按源图做 cluster bootstrap 的 95% CI | 下界 > 0.5 → 人偏好 qwen；上界 < 0.5 → 人偏好 comp；跨过 0.5 → 无差别 |
| H2 | critic 和人一致吗？ | critic 总分在 pair 上的成对准确率；与人整体评分的 Spearman（**编辑器内部**） | 成对准确率 ≥ 0.70 算可用；≤ 0.5 说明 critic 排序和人相反或无关 |
| H3 | 偏差来自哪个 critic？ | 每个 critic 对 6 个是/否题的 AUROC | 例：`appearance` 对「主体保留」AUROC ≈ 0.5、但对「光照一致」< 0.5 → 它在罚正确的重新打光 |
| H4 | gate 的判定人认不认？ | ip2p 中被 gate 判 0 的图，人在「背景换对」上答「否」的比例 | ≥ 80% → gate 可信（创新点 D 的人工佐证） |

结果怎么用：

* H1 = qwen 且 H2 成对准确率低 → 发现 1 成立，创新点 A 作主线；接着改 `appearance` / `light_harmony`（critics v3），
  在 **dev 划分**上调，用 **test 划分**报告提升。
* H1 = comp → critic 的排序其实是对的，主线退回 C（违例集评测）+ D（防 hacking）。
* H1 无差别 → 看分项偏好：通常会是「qwen 物理更好、comp 保留更好」，这本身就是 E6 的权衡结论。

## 1. 标注什么

全部标**每个任务最终选出的 best.png**（也就是 critic 打过分的那张）。

| 部分 | 内容 | 数量 | 作用 |
|---|---|---|---|
| 单图 | comp_v2 的 90 张 | 90 | H2、H3 |
| 单图 | qwen 的 90 张 | 90 | H2、H3 |
| 单图 | ip2p_v2 按 critic 分数分层抽 30 张：gate=0 / 0–0.6 / ≥0.6 各 10 | 30 | 提供低分样本、H4 |
| 单图 | 随机重复 20 张（换一个 id 再出现一次） | 20 | 标注人自身一致性 |
| 成对 | 同一任务的 comp vs qwen，左右随机 | 90 | H1、H2 |
| **合计** | | **230 单图 + 90 对** | |
| pilot | 从上面固定抽 20 单图 + 10 对 | 30 | 校准规范，不进正式结果 |

**dev / test 划分**：源图编号 `_01`、`_02` 为 dev（10 张源图、60 个任务），`_03` 为 test（5 张源图、30 个任务）。
每类（成人坐/河、成人站/山、成人站/河、狗坐/山、狗坐/河）各有一张进 test。改 critic 只看 dev，最后只报 test。

为什么按源图而不是按任务划分、做 bootstrap：90 个任务来自 15 张源图，同一张源图的 6 个任务高度相关，
把它们当 90 个独立样本会让置信区间过窄。

## 2. 标注题目与判定细则

### 单图（看原图 + 编辑结果）

| # | 题目 | 选项 | 判「否」的例子 |
|---|---|---|---|
| 1 背景 | 背景是否换成了目标场景，并且原场景基本看不到了？ | 是 / 否 / 不确定 | 只是整体调色（"雪" = 调冷色，"森林" = 调绿）；还能看到原来的河水；场景是目标的但像拼贴画 |
| 2 保留 | 主体是否还是同一个，姿态和动作没有变？ | 是 / 否 / 不确定 | 趴着变坐着、坐着变站着；少了/多了腿；换了衣服或毛色；脸变了 |
| 3 支撑 | 主体是否被一个合理的表面支撑着？ | 是 / 否 / 不确定 | 悬空；脚/身体陷进地面；坐在不可能坐的东西上（空气、墙、水面上） |
| 4 阴影 | 接触处的阴影是否合理？ | 是 / 否 / 不确定 | 接触处完全没有阴影；阴影方向与场景光源明显相反；阴影像一块黑斑 |
| 5 光照 | 主体的光照（亮度、色温、亮面方向）是否和新场景一致？ | 是 / 否 / 不确定 | 主体像从另一张照片剪下来的：暖色主体在冷色雪景里、背景逆光但主体正面打亮 |
| 6 边缘 | 主体边缘是否干净？ | 是 / 否 / 不确定 | 一圈亮边/光晕；残留旧背景（水、石头）；有奇怪的物体贴着主体轮廓长出来 |
| 7 整体 | 作为背景替换结果，整体有多可信？ | 1–5 | 1 完全失败（背景没换/主体毁了）· 2 明显问题 · 3 有瑕疵但能用 · 4 小瑕疵 · 5 看不出是编辑的 |

### 成对（看原图 + A + B）

| # | 题目 | 选项 |
|---|---|---|
| 1 | 整体上哪一张是更好的背景替换结果？ | A 更好 / B 更好 / 差不多 |
| 2 | 哪一张的主体保留得更好（同一个、姿态不变）？ | 同上 |
| 3 | 哪一张的主体和新场景在物理上更融合（支撑、阴影、光照、边缘）？ | 同上 |

### 关键规则（pilot 之前两人都要读一遍）

1. **光照变化不算「主体改变」。** 换到雪地后主体变亮、变冷色，换到室内后变暗，都是**应该**发生的。
   只有身份、姿态、形状、纹理变了才算第 2 题「否」。这是整个 E2 最重要的一条，因为它正是我们要检验的偏差。
2. **姿态改变一定算「否」**，哪怕新姿态在新场景里更自然。
3. **先判断、再放大。** 先看整图给第一印象（第 1、5、7 题），再按 `z` 放大看接触区和边缘（第 3、4、6 题）。
4. **「不确定」和「差不多」少用**，目标 < 10%。只有真的看不出来时才用，不要用来回避难题。
5. **只看当前这张。** 不要回忆别的图里同一张源图是怎么编辑的；不要猜是哪个编辑器做的。
6. **不要打开 `key.json`，不要看 critic 分数或 `runs/` 里的 panel 图**，直到两人都标完。
7. 遇到规则没覆盖的情况，在「备注」里写一句，pilot 讨论时统一。

## 3. 谁来标

* **至少 2 人**：你 + 一位队友。最好有一位没参与过 critic 设计的人（不知道我们希望看到什么结论）。
* 可选第 3 人：只标两人分歧的条目，用多数票。
* 两人**独立**标完正式轮之前不讨论具体图片。

## 4. 执行步骤

### 第 0 步：生成标注集（约 5 分钟，已经跑过一次）

```bash
python experiments/e2_build.py
# -> annotation/e2/manifest.json, key.json, images/*.jpg
```

`e2_build.py` 会拒绝覆盖已有的 `key.json`，因为标注结果是按 item id 记录的。要重新生成，先删掉整个 `annotation/e2/`。

### 第 1 步：给队友打包（如果队友用自己的电脑）

队友只需要 Python 3（不需要 GPU，也不需要装 requirements）：

```bash
# 只打包 manifest + images + 标注脚本；一定不要带上 key.json
cd annotation && zip -r e2_for_teammate.zip e2/manifest.json e2/images && cd ..
# 再单独发 experiments/e2_label.py 和本文档
```

队友运行 `python e2_label.py --annotator <名字> --dir e2`，标完把 `e2/labels/<名字>.jsonl` 发回来，
放进你的 `annotation/e2/labels/`。

### 第 2 步：pilot（每人约 20 分钟 + 一起讨论 30 分钟）

```bash
python experiments/e2_label.py --annotator siqi --pilot
python experiments/e2_analyze.py --pilot      # 两人都标完后
```

讨论时把两人答案不一样的条目逐个过一遍（`labels/*_pilot.jsonl` 里有每条答案和备注），
把达成的约定写进本文档最后的「裁定记录」。pilot 的标签不进正式结果。

**通过标准**：6 个是/否题里至少 5 个 κ ≥ 0.4。不达标的题目先改说明，必要时再做一轮 10 条的小 pilot。
注意 pilot 只有 30 条，κ 波动很大，主要用来发现**理解不一致**，不要过度解读数字。

### 第 3 步：正式标注（每人约 2.5–3 小时，分 4 次）

```bash
python experiments/e2_label.py --annotator siqi
```

* 顺序：先 230 张单图，再 90 对（每人的随机顺序不同）。先单图，是为了让绝对判断不受「和另一张比」的影响。
* 每次最多 45 分钟，休息后再继续；关掉网页或终端都不会丢，下次打开会从第一张未标注的继续。
* 速度参考：单图 30–40 秒，成对 15–20 秒。一张单图用了 2 分钟以上说明在纠结，按规则选、写备注、往下走。
* 快捷键：`1/2/3` 回答当前高亮的题（第 7 题是 `1–5`），`↑/↓` 换题，`Enter` 保存并下一张，`←` 上一张，`z` 放大。

### 第 4 步：分析（10 分钟）

```bash
python experiments/e2_analyze.py                     # 全部 -> annotation/e2/report.md
python experiments/e2_analyze.py --split test        # 只看 test 划分
# 改完 critic 并 rescore 之后：
python experiments/e2_analyze.py --split test --map comp_v2=<rescored run> --map qwen=<rescored run>
```

报告里有三部分：

1. **标注一致性**：每题的一致率和 Cohen's κ（1–5 评分用二次加权 κ），以及每人对 20 个重复项的自身一致性。
2. **人对编辑器的判断**：每个编辑器每题答「是」的比例和平均评分；qwen vs comp 的胜率和 95% CI（H1）。
3. **critic 与人的一致性**：每个分数（总分、各分支、加权和、去掉 keep 的 follow×world）的成对准确率；
   与人评分的 Spearman（全部 / 每个编辑器内部）；每个 critic 对每道是/否题的 AUROC（H2、H3）。
   AUROC 只用两人答案一致的条目。

## 5. 常见的坑

* **看过 critic 分数再标**：会不自觉地向分数靠拢。所以在两人标完之前，不要打开 `runs/*/panel_best.jpg` 和 `report.json`。
* **把光照变化当保留失败**：这会把我们要检验的偏差直接复制进标签里。见规则 1。
* **用全部 90 个任务调 critic 再在同样的数据上报告**：属于在测试集上调参。dev 上调、test 上报。
* **把 90 个任务当独立样本**：CI 会太窄。分析脚本已经按源图做 bootstrap。
* **重新生成标注集**：item id 会变，已有标签全部失效。`e2_build.py` 默认拒绝覆盖。
* **只有一个人标**：没有 κ 就没法证明标签可靠，审稿人一定会问。
